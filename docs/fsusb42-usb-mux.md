# FSUSB42 — USB Multiplexer Control

Two **FSUSB42** devices (TI USB 2.0 High-Speed switch, DPDT: one D+/D− input pair
routed to one of two output pairs, 10-lead UQFN) implement the KVM USB channel
select. This page documents the **chip-level control semantics verified against the
firmware**. Channel routing and the full board wiring are in
[`circuit-ir-usb-mux.md`](circuit-ir-usb-mux.md).

> **Provenance / correction.** The board silkscreen and the exported schematic
> (`USBMUX` PCB, refdes `U1-FSUSB42MUX` / `U2-FSUSB42MUX`) identify the mux as the
> **FSUSB42**, not the SN74CB3Q3253 named in the legacy `sn74cb3q3253_pinmap.html`.
> The control semantics below are unchanged because both parts expose the same
> interface: a **select** line plus an **active-low output-enable** (`S` and `OE_n`
> on FSUSB42). Per-pin physical numbers are still omitted — confirm them in the TI
> FSUSB42 datasheet (SNVS774) before wiring.

## Control semantics (verified in firmware)

Each chip is driven by two signals — a select and an output enable:

| Signal | Behaviour |
|---|---|
| `MUXn_SEL` | 0 → Y0 path, 1 → Y1 path |
| `MUXn_OE`  | **active low**: 0 = chip enabled, 1 = all ports Hi-Z (device appears unplugged) |

Firmware evidence: `setKvmChannel()` in `firmware/MegaKey_IO/MegaKey_IO.ino`
(direct GPIO) and the `SR_BIT_MUX*` block in
`firmware/MegaKey_AVR128DB64/MegaKey_AVR128DB64.ino` (74HC595 bits).

| Channel | SEL1 | OE1 | SEL2 | OE2 | Meaning |
|---|---|---|---|---|---|
| CH1 | 0 | 0 | X | 1 | chip 1 only, Y0 → PC1 |
| CH2 | 1 | 0 | X | 1 | chip 1 only, Y1 → PC2 |
| CH3 | X | 1 | 0 | 0 | chip 2 only, Y0 → PC3 |
| CH4 | X | 1 | 1 | 0 | chip 2 only, Y1 → PC4 |
| CH5 (JAMMA) | X | 1 | X | 1 | both Hi-Z — USB fully disconnected |

## Control signal sources

| Signal | Mega 2560 (v3.4) | AVR128DB64 (v4.0) |
|---|---|---|
| MUX1_SEL | GPIO `A10` | 74HC595 bit 6 |
| MUX1_OE  | GPIO `A12` | 74HC595 bit 7 |
| MUX2_SEL | GPIO `A14` | 74HC595 bit 8 |
| MUX2_OE  | GPIO `A15` | 74HC595 bit 9 |

## Wiring notes

- USB D+/D- is a differential pair: FSUSB42 is a DPDT (double-pole double-throw)
  switch, so one D+/D− input pair routes to one of two output pairs together — this
  is exactly what a full USB pair needs. Which player pair feeds which chip's common
  port must match the PCB netlist — verify against the board silkscreen/datasheet pin
  assignment when servicing.
- Decoupling: 0.1 µF ceramic directly between VDD and GND of each chip.
- Supply is 3.0–3.6 V (FSUSB42 VDD); USB signal levels are within spec since the
  switch passes the line end-to-end (signal is generated by the 3.3 V RP2040 hosts/devices).
- OE=1 on both chips (CH5) intentionally makes every host see an unplug — JAMMA mode
  uses the JVS bus on the AVR instead of USB.
